# 교수 자료 제작

로컬 프로필과 수업 설계를 읽는다. 산출물 종류가 정해지지 않았으면 먼저 "교관 진행안, 학습자 실습지, 슬라이드 중 무엇부터 만들까요?"라고 묻는다. 수업 주제·학습 목표·차시 시간을 바꾸어야 하면 이유를 먼저 설명한다.

## 자료별 기본 구성

| 자료 | 포함할 내용 | 템플릿 |
|---|---|---|
| 교관 진행안 | 목표, 사전 준비, 시간표, 질문·전환 멘트, 관찰 포인트, 대안 활동 | `instructor-brief.md` |
| 학습자 실습지 | 목표, 상황·문제, 단계별 수행, 제출물, 자기 점검, 도움말 | `practice-sheet.md` |
| 슬라이드 원고 | 한 장의 핵심 메시지, 화면 내용, 교관 설명, 활동 전환, 출처 | 수업 설계를 바탕으로 새 원고 작성 |

한 슬라이드에는 핵심 메시지 하나를 두고 설명 대본과 화면 글을 분리한다. 활동 안내에는 수행 시간과 완료 기준을 쓴다. 자료에 출처가 필요하면 실제 확인한 제목·주소·접근일만 기록한다. 사용자가 주지 않은 로고·부대 마크·공식 서식을 임의로 만들지 않는다.

## 파일 형식

- Markdown 원고는 기본 환경만으로 작성할 수 있다.
- PPTX 요청 시 설치된 `pptx-maker` 또는 관련 스킬의 안내·도움말을 먼저 확인한다. HWPX 요청은 `hwpx-new`, 기존 문서 읽기는 `kordoc`이 있는지 확인한다.
- 도구가 없으면 원고와 설치 필요 사항을 구분해 알려 준다. 확장자만 바꾸거나 파일을 만들지 않고 완성했다고 말하지 않는다.
- 새 패키지·유료 API·클라우드 서비스 연결은 자동 실행하지 않는다. 파일 생성 도구가 있더라도 외부 업로드 없이 가능한 경로를 우선한다.
- Linux 내장 렌더러로 만든 PDF는 실제 한글·PowerPoint 배치와 다를 수 있다. 사용한 렌더러와 확인 범위를 기록한다.

## 배포 전 확인

1. 목표·활동·평가 기준의 표현과 숫자가 자료 사이에 일치하는지 확인한다.
2. 학습자에게 불필요한 교관 메모나 정답이 실습지에 섞이지 않았는지 확인한다.
3. 그림·표·색상에만 의존하지 말고 텍스트로도 의미를 전달한다.
4. 실제 파일이 만들어졌다면 열기·렌더·쪽 넘침 등 가능한 검사를 수행한다. 못 한 검사는 명확히 남긴다.
5. 공개·가상 사례만 포함했는지, 개인 프로필·학생 자료·내부 문서가 섞이지 않았는지 확인한다.

완료 답변에는 파일 경로, 자료 구성, 실제 검증 결과, 가정·미확인 항목을 짧게 적는다. 사용자의 별도 요청 없이 GitHub·메신저·이메일로 자료를 보내지 않는다.
